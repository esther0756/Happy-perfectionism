# 행복한 완벽주의

**나를 이해하는 것부터, 나에게 맞는 하루를 만드는 것까지.**

Next.js App Router, TypeScript, Tailwind CSS로 만든 첫 버전입니다. 로그인, 데이터베이스, API 서버 없이 정적 사이트로 동작합니다. 아이보리·세이지 그린·따뜻한 주황을 사용하며 휴대폰, 태블릿, PC 화면을 지원합니다.

## 시작하기

Node.js 22 이상과 npm이 필요합니다. 비밀키나 환경변수 설정은 필요하지 않습니다.

```bash
cd Happy-perfectionism
npm ci
npm run dev
```

개발 서버는 3000번 포트를 사용합니다. 이 클라우드 환경에서 기본 npm 캐시 디렉터리에 쓸 수 없다는 오류가 발생하면 `npm ci --cache /tmp/happy-npm-cache`를 사용하세요.

프로덕션 빌드와 로컬 확인:

```bash
npm run build
npm run start
```

`next.config.ts`의 `output: "export"`로 `out/`에 정적 HTML·CSS·JavaScript를 생성합니다. `start`는 `next start` 대신 정적 파일 서버인 `serve`를 사용합니다. 서버 프로세스에 검사 응답이나 활동 기록을 보내는 API는 없습니다.

메뉴의 **‘쉼도 계획의 일부예요’**에서 25분 또는 50분 후 휴식 팝업을 설정할 수 있습니다. 페이지를 이동해도 타이머가 유지되며, 새로고침하거나 사이트를 닫으면 종료됩니다. 탭이 비활성화되어 타이머 실행이 지연되어도 돌아온 시점에 실제 경과 시간을 확인합니다. 운영체제 푸시 알림은 사용하지 않습니다.

기록장에서는 날짜를 선택하거나 ‘오늘’ 버튼·이전 기록 선택 메뉴로 다른 날을 확인합니다. 실행하지 못한 할 일을 다음 날로 자동 이동하지 않으며, 매일 현실적인 계획을 새로 세울 수 있습니다. 도움을 요청할 사람은 기록만 하며 메시지를 보내지 않습니다.

## 검사 채점 — 제공 자료의 유형별 합산

사용자의 요청에 따라 유형별 합산 결과를 활성화했습니다. 20문항에 모두 답하면 가장 높은 유형을 크게 표시하고, 둘째 유형이 첫째 유형과 **2점 이내**이면 작은 카드로 함께 보여줍니다. 네 유형의 합산 점수도 모두 확인할 수 있습니다.

사용자가 제공한 이미지의 문항과 출처를 옮겼습니다.

- 이미지에 적힌 출처: 윤닥(2022), 『오늘도 시작하지 못하는 당신을 위해』, 한빛비즈.
- 이미지에 나타난 배정: 1~5 회피형, 6~10 감독형, 11~15 자책형, 16~20 안정형.
- 이미지의 안내: 유형별 합산 점수가 높은 순서대로 정리.
- `src/config/assessment.ts`에서 원래 문항 번호별 유형 배정, 합산 방식, 둘째 유형 표시 기준(`secondaryMaxGap: 2`)을 관리합니다. 각 유형은 5문항, 5~20점입니다. 역채점이나 가중치는 추가하지 않았습니다.
- 이미지에서 확인할 수 있는 척도 양 끝의 문구만 사용합니다. 2·3점의 명칭을 임의로 확정하지 않았습니다.
- 응답은 문항의 고유 ID에 연결하므로 표시 순서를 섞거나 뒤로 돌아가도 다른 문항으로 옮겨가지 않습니다.

최고점이 같으면 모두 공동 1위로 같은 비중으로 보여줍니다. 이 경우 더 낮은 순위의 유형을 둘째 유형으로 올리지 않습니다. 최고점이 하나이고 2위가 동점이라면, 2점 차이 조건을 충족하는 공동 2위들을 모두 작은 카드에 표시합니다. 모든 점수가 같아도 특정 유형을 임의로 선택하지 않습니다.

한 문항이라도 빠졌거나 1~4의 정수 이외 값이 있으면 결과를 계산하지 않습니다. 응답 수정 후에는 합계와 결과를 다시 계산합니다. 둘째 유형의 2점 차이는 사용자가 선택한 **화면 표시 기준**이며, 임상적으로 검증된 기준점은 아닙니다. 결과 활성화는 검사의 심리측정학적 타당도 검증을 의미하지 않습니다.

유형 설명의 기본 틀은 제공 자료를 참고했고, 강점·질문·실천 제안은 자기이해용으로 편집했습니다. 전문적인 심리 진단이나 치료 도구가 아닙니다.

## 개인정보와 기록

- 검사 응답과 계산된 점수·유형 결과는 React 메모리에서만 다룹니다. `localStorage`, 쿠키, URL, 서버에 기록하지 않습니다. 결과에 따라 달라지는 링크는 자동 미리 불러오기를 끕니다. 사용자가 직접 유형 안내·맞춤 연습 링크를 누르면 해당 공개 페이지의 경로나 유형 선택값만 사용합니다.
- 가치·에너지·마음 연습·날짜별 할 일과 회고는 **같은 기기·브라우저에 기본 자동 저장**합니다. 입력 시 동기적으로 저장하며, 저장 성공 후에만 저장 상태와 시간을 갱신합니다. 검사 응답은 제외합니다.
- `localStorage`의 기존 `happy-perfectionism:v1` 키를 유지합니다. 기존 활동 데이터는 그대로 읽고, 다음 저장부터 `storageVersion: 2` 봉투에 데이터와 저장 시간을 담습니다.
- 보관을 끄면 저장된 개인 기록은 삭제하고 현재 화면에서만 이어 씁니다. 전체 삭제는 현재 활동·검사 응답까지 지웁니다. 두 경우 모두 개인 기록 없는 ‘저장 꺼짐’ 표시만 남아 다음 방문에도 설정이 유지됩니다.
- 같은 브라우저의 다른 탭에서 바꾼 기록·저장 설정도 반영합니다. 기록 삭제 후 다른 탭의 이전 데이터가 자동 저장으로 되살아나지 않도록 처리합니다. 여러 탭에서 같은 항목을 동시에 편집하면 마지막 편집이 반영됩니다.
- **저장·백업 및 개인정보**에서 JSON 백업 파일을 내려받고 복원할 수 있습니다. 파일에는 활동 기록만 포함하며 설정·검사 응답·결과는 제외합니다. 복원은 파일 형식과 길이를 검증하고, 현재 기록을 대체한다는 확인 뒤 적용합니다. 최대 파일 크기는 10MB입니다.
- 공유 기기에서는 같은 브라우저를 사용하는 다른 사람이 기록을 볼 수 있습니다. 계정별 인증·암호화·자동 기기 간 동기화는 제공하지 않습니다. 다른 기기에서는 백업 파일을 직접 불러옵니다. 브라우저 데이터를 지우기 전 백업을 권장합니다.
- Zod로 저장소와 백업 형식을 검증합니다. 손상된 저장본은 자동으로 덮어쓰지 않습니다. 저장소가 차단되거나 용량이 부족해도 현재 화면에서 작성·파일 백업을 할 수 있고, 실패 상태와 재시도를 제공합니다.
- 분석 스크립트, 광고, 외부 폰트 요청을 넣지 않았습니다. Noto Sans KR은 패키지에 포함되어 자체 호스팅됩니다. 아이콘과 삽화도 사이트 안에 포함됩니다.
- Vercel 등의 호스팅 사업자가 일반적인 접속 로그를 처리할 수 있습니다. 실제 배포 시 별도 분석 서비스나 로그 수집에 입력값을 추가하지 마세요.

학교 외부 링크는 경력개발센터(`career.snu.ac.kr`)와 대학생활문화원(`snucounsel.snu.ac.kr`)의 홈페이지를 엽니다. 특정 검사의 직접 신청 URL을 추정하지 않았습니다. 이 개발 환경에서는 두 도메인의 연결이 네트워크 정책의 403 응답으로 차단되어 실제 프로그램 운영·신청 페이지를 확인하지 못했습니다. 공개 배포 전에 일반 브라우저에서 링크와 현재 운영 안내를 확인해주세요.

## 검증

```bash
npm run lint
npm run typecheck
npm run build
npx playwright install chromium
npm test
```

시스템에 `/usr/bin/chromium`이 있으면 다운로드 없이 사용합니다. 별도 설치 위치는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 지정할 수 있습니다. 테스트는 빌드된 `out/`을 3000번 포트에 올리고 실행합니다. 3000번 포트가 이미 사용 중이면 그 프로세스를 확인하고 테스트 서버와 충돌하지 않게 하세요.

자동 검증 범위: 유형별 합산, 섞인 문항의 ID 유지, 2점 차이 경계, 공동 1·2위, 전 유형 동점, 미응답·잘못된 값 차단, 응답 수정 후 재계산, 응답·결과 비보관, 할 일·날짜별 회고, 활동 저장 선택·해제·삭제, 저장소 오류, 가치 3개 제한, 활동 전달, 휴식 팝업, 반응형 탐색과 결과 화면, axe를 통한 색상 대비·폼 이름 등 접근성 검사. 화면 캡처는 `test-results/`에 생성됩니다. 자동 접근성 검사가 모든 보조기기와 브라우저의 사용성을 보장하지는 않습니다.

## GitHub Pages 미리보기

GitHub Pages에서는 저장소 이름을 URL 경로로 사용하므로 아래처럼 빌드합니다. 로컬 개발과 Vercel에서는 이 환경변수를 설정하지 않습니다.

```bash
NEXT_PUBLIC_BASE_PATH=/Happy-perfectionism npm run build
```

`out/`의 내용과 `.nojekyll`을 `gh-pages` 브랜치의 루트에 게시합니다. 애플리케이션 소스와 `node_modules`는 이 브랜치에 넣지 않습니다. `public/.nojekyll`은 이후 빌드에도 자동으로 포함됩니다.

최초 한 번 GitHub 저장소의 **Settings → Pages → Build and deployment**에서 **Deploy from a branch → gh-pages → /(root) → Save**를 선택해야 합니다. 활성화와 GitHub 배포가 완료되면 `https://esther0756.github.io/Happy-perfectionism/`에서 접속할 수 있습니다. 브랜치에 파일을 올리는 것과 Pages 활성화·배포 완료는 별도 단계입니다.

## Vercel 배포

1. 이 변경 사항을 GitHub 저장소에 커밋하고 푸시합니다.
2. Vercel에서 **Add New → Project**로 `Happy-perfectionism` 저장소를 가져옵니다.
3. 프레임워크는 **Next.js**, 프로젝트 루트는 이 `package.json`이 있는 디렉터리로 선택합니다.
4. Node.js는 **22 이상**, 설치 명령은 `npm ci`, 빌드 명령은 `npm run build`를 사용합니다. Output Directory는 Next.js 프리셋의 자동 감지를 사용하세요. 일반 정적 사이트 프리셋을 선택한 경우에는 `out`으로 지정합니다.
5. 환경변수·DB·API 키 없이 Deploy를 실행합니다.
6. 배포 주소에서 모바일 메뉴, 테스트 완료 안내, 기록 보관·삭제, 휴식 알림, 기관 링크를 확인합니다.

또는 Vercel CLI에 로그인한 뒤 프로젝트 루트에서 `npx vercel`로 미리보기 배포하고, 확인 후 `npx vercel --prod`로 배포할 수 있습니다.

Vercel 외에도 `out/`을 디렉터리별 `index.html`을 지원하는 정적 호스팅에 배포할 수 있습니다. 소스 폴더 전체나 개발 서버를 공개하지 말고 빌드 결과만 배포하세요.
